## Task 1: Engine — multi-listener `http.Server` and `host` header

Bug found from source code: W2 §06 and the W3 `server.js` call `createServer(listener)` **and then** `server.on('request', …)`. In Node both listeners run; the simulator's `on('request')` currently *replaces* the handler, which would drop the response.

**Files:** modify `engine/node-sim.js`, `engine/net-sim.js`; tests in `tests/node-sim.test.js`, `tests/net-sim.test.js`.

- [ ] Failing tests: (a) `createServer(h1)` then `server.on('request', h2)`: both run for one request and the response from `h1` is returned; (b) an async `h1` rejection still rejects the request when `h2` exists; (c) `req.headers.host === 'localhost:3000'` for a server listening on 3000 (and the explicit `port` option wins).
- [ ] Implement: `Server` keeps `#handlers[]`; dispatch calls all and returns `Promise.all` of the thenables (or `undefined`). `net-sim` sets `host` to `localhost:<port>` (explicit `port`, else the last listening port, else 3000).

## Task 3: Widgets — `event-loop`, `url-anatomy`, `verb-quiz`

**Files:** modify `js/widgets.js`, `css/app.css`.

## Execution notes

Found while running; later plans inherit these.

1. **`http.Server` listeners:** `createServer(h)` + `server.on('request', h2)` now runs *both* (Task 1). `req.headers.host` is `localhost:<port>`.
2. **`server.listen(port, cb)` callback runs as a microtask** (not `setTimeout`), so `console.log` inside the callback (as in the slides) is part of the first Run's output. Test in `tests/runner.test.js`.
3. **Adaptive response timeout:** `runProject` default is 300 ms; after the first timeout in a session later waits are `min(timeout, 40 ms)`. Without this the `x-endpoints` starter (9 unanswered requests) would exceed the 3 s sandbox limit and show the misleading "infinite loop" message. Verified live: 1.3 s.
4. **Exercise checks beyond HTTP:** `expect.textExcludes`, test-level `logIncludes` (for code no route reaches), and block-level `codeChecks` (`{name, file?, pattern, mustMatch?}` over comment-stripped source). `tests/content.test.js` counts code checks when deciding "starter must fail / solution must pass". If the entry run crashes (e.g. a `ReferenceError`), the UI shows that error in the Output panel, which is the intended lesson for the W3 bug-hunt exercises.
5. **Content authoring:** code samples containing `${…}` or backticks live in template literals with `\${` / `\`` escapes; a literal `\n` inside sample code is written `\\n`. Files that a learner edits must be listed first in `files` (the solution replaces the first file); `entry` selects what runs.
6. **Verified live (local preview):** W2 — 4 experiments respond, 8/8 exercises fail→pass; W3 — quiz 6/6, URL anatomy, 3 multi-file/status experiments, 8/8 exercises fail→pass; no console errors.
